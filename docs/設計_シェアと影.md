# 設計：シェア動画・鬼面・影（GHOST）の登録と対戦

2026-11-05 にヒデキと決めた進め方。企画書「見た目とシェア」「コンセプト：影と戦う」「影レースとマッチング」を、第1段階の端末だけの形で先に作る。

## 決めたこと

| 論点 | 決定 |
| --- | --- |
| 対戦の相手 | まずサーバー無し。自分の過去の影と、影のファイルを送り合って対戦する。後でサーバーへ移せる形にしておく |
| シェア動画 | 決め場面（とどめ・技が決まった瞬間・影を追い越した瞬間）を自動で切り出し、10〜15秒の縦動画にまとめる |
| 師範の影 | 影を録る機能を先に作り、ヒデキが秘伝などを録って全員用のデータにする |
| 作る順 | ①シェアの実機テスト（済：`share.html`）→ ②影の登録 → ③影との対戦 → ④決め場面の切り出し |

## ① シェアの実機テスト（`share.html`）

表紙の「シェア動画（試験）」から開く。

- 前のカメラの映像を自撮りのように左右反転し、縦9:16の真ん中を使う
- 骨格推定（本体と同じMediaPipe）の両目の位置に、鬼面の両目の基準点（`data/masks.json` の eyeL・eyeR）を重ねる。拡大・回転・移動だけで合わせる。揺れは `share.smooth` で抑える
- キャンバスを `captureStream` で録画し（`MediaRecorder`、iPhoneはmp4のはず）、終わったら共有シート（`navigator.share` のファイル共有）に渡す。共有できない端末では保存のリンクを出す
- 映像が外に出るのは「共有」を押したときだけ（決定事項どおり）
- 画面の下に「この端末でできること」を出す。iPhoneで次を確かめる
  - camera：縦（720×1280など）で来るか
  - pose：骨格推定のコマ数（録画中に落ちないか）
  - captureStream・MediaRecorder・format：録画できるか、mp4か
  - share files：共有シートにファイルを渡せるか

## ② 影の登録（次に作る）

影は動画ではなく**骨格のデータ**（企画書どおり）。

- 録るもの：時刻ごとの3Dの手の位置と、全身の骨格（33点のうち描くのに要る点）、判定の結果（型・剣速・COMBO・技・ダメージ）
- 長さ：1体の戦い、または技1つ分。30fpsで数百KBの見込み。容量を減らすため、座標は小数3桁、コマは15fps程度に間引く
- 体格の差：再生するときに、見る人の肩幅と身長に合わせて伸び縮みさせる
- 保存：端末の中（自分の影）。書き出すと1つのファイル（`.ghost.json`）になり、LINEなどで送れる。受け取った人は読み込むと対戦できる
- 師範の影：ヒデキが録って書き出したファイルを `data/ghosts/` に入れると、全員が見本・相手として使える

## ③ 影との対戦（影レース）

- 同じ妖怪・同じ条件（妖怪の種類・HP・判定の段階）で、影の記録を時刻どおりに再生する
- 画面には影を半透明のグレーで描き、影のダメージで影側の妖怪のHPも減っていく
- どちらが先に倒すかで勝ち負け。影であることは正直に示す（名前と国）
- 影を追い越した瞬間に、影が斬られて散る演出（企画書「影斬り」）

## ④ 決め場面の切り出し

- 戦いの間、直前の数秒をいつも録画しておく（古い部分は捨てる）
- とどめ・技・影斬りなどが起きたら、その前後を切り出して保存する
- 終わったら、切り出した場面をつないだ10〜15秒の動画にして共有に渡す
- 録画は重いので、①の実機テストで骨格推定のコマ数が落ちないかを見てから作り方を決める

## サーバーに移すとき（第2段階）

- 影のファイルの形はそのまま使い、置き場所を端末からサーバーに変える
- アカウント、ランキング、影のマッチング、不正対策（人間に不可能な速さの記録の除外）はそこで作る
