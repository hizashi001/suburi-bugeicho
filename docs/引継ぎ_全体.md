## 5. 次にやること（ヒデキと相談中の順番）

影（GHOST）はこのアプリの核。2Dに落とすと見劣りするのを心配して、3Dの可能性を試している。

1. **靄の描き方**：今の `shadow.vrm` で、体の表面から靄が立ちのぼり、縁が煙のように溶け、動いた跡に靄の尾を引く描き方を作る（モデルに依らない）
2. **腕と脚を骨格の点に直接向ける**：Kalidokit（関節の角度を間接に推す）をやめ、骨格推定の3Dの点の方向へ骨を直接向ける計算にして、手先の位置を合わせる
3. **刀の追い方**：別のチャットで「刀を見つけるAI」を作っている（`docs/引継ぎ_刀検出AI.md`）。それまでのつなぎとして、両手の握りから刀の向きを推す（MediaPipeの手の推定）や、刀に色テープを貼る精密モードも候補
4. **影との対戦（影レース）**：自分の過去の影・受け取った影・師範の影が、同じ妖怪を相手に並んで戦い、先に倒した方が勝ち。`docs/設計_シェアと影.md` の③
5. **決め場面の切り出し**：とどめ・技・影を追い越した瞬間を、10〜15秒の縦動画に自動でまとめる（④）

決まっていないこと：

- 3Dの影を採用するか（`CLAUDE.md` は「3Dアバターは作らない」のまま。採用するなら書き換える）
- 3Dの侍のモデル：Tripo3Dなどで作る案。袴は脚と一緒に曲がらない形にする、面の数は3万程度まで、商用の利用規約を確かめる
- `shadow.vrm` の扱い：VRMの中の利用条件が「再配布しない・改変しない」のまま公開のリポジトリにある（ヒデキ自身が作者）。中の模様の画像を抜けば9.5MB→1MB程度にできるが、ヒデキの了承待ち
- 防具・刀・影絵の画像は保留（背景抜きと軽量化はまだ）

## 6. 作業のときの注意

- **試験は偽のカメラ**（`tools/test/`）。判定の細かさ・重さ・Safari特有のことは実機でしか分からない。実機で確かめていないことを「動く」と言わない
- `pkill -f "http.server 876[5]"` のように `[5]` を付ける（付けないと pkill が自分を止める）
- 画像や音の取り込み：
  - GitHubのサイトから上げるときは、最後の緑の「Commit changes」を押さないと入らない
  - Windowsでは `.mp3.MP3` のような二重の拡張子になりやすい
  - 妖怪は600×800・256色に縮める。鬼面は背景を抜いて目の位置をそろえる（`tools/masks/`）
  - 取り込んだら `data/asset_imports.json` に足し、`python3 tools/asset_list.py` を回す
- 画面の文言は必ず `lang/ja.json` と `lang/en.json` の両方へ（`python3 tools/test/keys.py` で抜けを確かめる）
- 数値は `config/balance.json` へ。`_note` に日本語で意味を書く
- iPhoneで起きたエラーは、画面の下に赤い枠で出る（全ページ）。ヒデキにはスクリーンショットを頼む
