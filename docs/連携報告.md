### A2. 振りの判定の出入り

#### 流れ

骨格推定（MediaPipe、手首の位置）→ `detector`（2664行。手の速さから1振りを切り出す）→ `onMeasure(m)`（1720行）→ `judge(m)`（1686行。どの型か、通すか）→ `onSwing(m, j)`（1737行。ダメージ）。

カメラは刀を見ていない。両手首の3Dの位置（腰が中心、メートル）だけを見ている。

#### 測った値 `m`（`detector.measure` 2716行が作る）

| 項目 | 中身 |
|---|---|
| `peak` | 手の最高の速さ（m/s） |
| `dir` | 振りの向き。長さ1の `[右, 下, カメラ側]`。鏡に映った自分から見た向き |
| `amp` | 振り幅（m）。始点から終点まで。0.18m 未満は捨てる |
| `wob` | ぶれ（直線からの最大のずれ ÷ 振り幅） |
| `dip` | 途中の減速（最高速に対する割合） |
| `settle` | 振り終わった後0.28秒の手の速さの平均（残心。小さいほど止まっている）。流れの途中で切った振りは 0.5 固定 |
| `tStart` `tEnd` | 始まりと終わりの時刻（`performance.now()` のミリ秒） |
| `from` | 振り始めの手の位置 `[右, 下, カメラ側]`（腰が0、m） |
| `demo` | 試し振りの時だけ `true` |

#### 判定の結果 `j`（`judge(m)` が返す）

| 項目 | 中身 |
|---|---|
| `t` | 一番近い型。`t.id` が種類（下の9つ、または追加した型の id） |
| `tm` | 比べた手本（登録した型。未登録なら標準の値） |
| `ang` | 手本との向きの差（度） |
| `sp` | 速さ（手本の最高速に対する割合。1.0＝手本どおり） |
| `ampR` | 振り幅（手本に対する割合） |
| `wobEx` `dipEx` | ぶれ・減速が、手本より多かった分 |
| `ok` | 今の難易度で一振りと認めたか |
| `reasons` | 認めなかった理由の文言 |

型の id：`shinmen`（真向）・`kiriage`（切り上げ）・`kesa`（袈裟）・`gyakukesa`（逆袈裟）・`kesaage`（袈裟切り上げ）・`gyakukesaage`（逆袈裟切り上げ）・`do`（胴）・`gyakudo`（逆胴）・`tsuki`（突き）。

きれいさは `scoreSwing(m, j)`（1707行）が返す。`line`（軌道 0〜40）・`ampPts`（振り幅 0〜30）・`zan`（残心 0〜30）・`form`（3つの合計 0〜100）・`speedScore`（0〜100）・`score`（速さと形の平均）・`rank`（S 85以上・A 70以上・B 50以上・C）。

#### 難易度で変わること

5段階。値は `config/balance.json` の `judge.levels`。空欄はその段階では見ない。

| 段階（画面の名前） | 速さ | 振り幅 | 向きの差 | ぶれ | 減速 | 軌道係数の下限 | 得点の倍率 | 怯みの向き | とどめは強い一振りでよい |
|---|---|---|---|---|---|---|---|---|---|
| 0 入門 | 0.30以上 | 0.25以上 | — | — | — | 0.7 | ×1.0 | 70度 | はい |
| 1 初段 | 0.40 | 0.35 | 70度まで | — | — | 0.6 | ×1.1 | 60度 | はい |
| 2 三段 | 0.55 | 0.45 | 55度 | 0.45 | 0.6 | 0.5 | ×1.25 | 50度 | はい |
| 3 師範 | 0.70 | 0.55 | 40度 | 0.3 | 0.4 | 0.4 | ×1.5 | 40度 | はい |
| 4 神域 | 0.85 | 0.65 | 30度 | 0.2 | 0.25 | 0.3 | ×2.0 | 25度 | いいえ |

- 変わるのは「通すかどうかの門」と、ダメージの軌道係数の下限、得点の倍率。**どの型に見えたか（`t`）と、測った値（`ang` `sp` など）は難易度によらず同じ。**
- 段階の名前が2か所で食い違っている。`lang/ja.json` は「入門・初段・三段・師範・神域」、`balance.json` の `_note` は「入門・初段・二段・三段・免許皆伝」。画面に出るのは前者。

#### 試験の時だけ難易度を指定できるか

- **今はできない。** `judge(m)` は設定で選んだ難易度（`S.diff`）を直接読む。引数は無い。
- **ただし、`judge` を変えずに作れる。** `judge` は通さなかった振りでも測った値を全部返すので、試験の側で `j.sp` `j.ang` `j.ampR` `j.wobEx` `j.dipEx` を、指定した段階の値（`judge.levels[n]`）と比べ直せばよい。「どの段階まで通ったか」も同じやり方で分かるので、「緩めずに合格」の印も付けられる。

#### 並びと間隔の判定

| 項目 | 今の作り |
|---|---|
| 並びの判定 | **ある。** `onSwing` の1760〜1765行。コンボの中で通った型を `P.formSeq`（最大12）に溜め、登録済みの技の `seq` と末尾が一致したら技が決まる。長い技を優先。決まると必ずクリティカル、倍率は `tech.mult`（1.5） |
| 間隔の判定 | **技ごとには無い。** あるのはコンボの受付だけ（前の振りの終わりから次の振りの始まりまで。木刀で約1.67秒。得物の重さで1.4〜3.0秒）。受付を過ぎるか、形の点が15未満だと並びは最初からになる |
| 時刻 | 1振りごとに `tStart` `tEnd` があるので、「それぞれの間は1秒以内」は計算できる |
| 一筆書き | 止まらずに流れる動きも、折り返しや向きの変化で1振りずつに分かれる（`detector.split` 2697行） |
| 動く場面 | 妖怪退治と登頂の戦闘中だけ。試験用の場面は無い |

#### `data/techniques.json` の形と、今の中身

```json
{
  "forms": [
    { "id": "c_xxx", "name_ja": "居合", "name_en": "Iai",
      "dir": [1, 0, 0], "amp": 0.6, "peak": 4.2, "kg": 0.6,
      "wob": 0.15, "dip": 0.15, "from": [0.1, 0.05, 0.2] }
  ],
  "techniques": [
    { "id": "my_xxx", "name_ja": "技の名前", "name_en": "Name",
      "seq": ["kesa", "kesa", "do"], "mult": 1.5 }
  ]
}
```

- **今は `forms` も `techniques` も空（0件）。** 全員用の技は1本も無い。
- `seq` は型の id の並び（2〜12個）。間隔や速さの項目は無い。
- 端末で作った技は `S.techniques`、追加した型は `S.customForms` に入り、型の登録画面の「書き出す」でこの形にコピーできる。
- 秘伝は別で、`balance.json` の `hiden`（今は仮の「袈裟→逆袈裟→突き」）。週替わりの仕組みは無い。

#### 結論

- **極みの試練を「基本の振りの並びと速さ」で書ける。** 並びは今の仕組みと同じ考え方、間隔は `tStart` `tEnd` から、速さは `j.sp` から取れる。足りないのは、技ごとの間隔と速さを書く項目と、試験用の場面だけ。
- **救済を「試験の判定を緩くする」形で作れる。** `judge` には手を入れない。
- 注意：突きは認識されにくい（`CLAUDE.md`）。試練の並びに突きを入れると、判定のせいで落ちる人が出る。

### A4. 影の記録

#### 保存の形

IndexedDB の `ghost-store`。表は2つで、`meta`（一覧用の小さい情報）と `data`（コマを含む全部）。部品は `js/ghost.js`。ファイルに書き出すと `名前.ghost.json`（中身は `data` の1件と同じ）。

```json
{
  "format": "ghost/1",
  "id": "g_m3k2x9ab",
  "created": "2026-11-05T12:34:56.000Z",
  "kind": "fight",
  "master": false,
  "name": "",
  "fps": 15,
  "aspect": 0.75,
  "points": [0, 11, 12, 13, 14, 15, 16, 23, 24, 25, 26, 27, 28],
  "frames": [[0, 0.512, 0.231, 0.44, 0.35, "…13点ぶんの x,y…"], [67, "…"]],
  "events": [[1830, "swing", "kesa", 142, 3]],
  "durationMs": 14200,
  "mode": "run",
  "division": "bushi",
  "diff": 0,
  "weapon": { "opt": "bokuto", "kg": 0.6, "kind": "katana" },
  "lv": 4,
  "yokai": { "id": "kappa", "asset": "yokai_001_kappa", "variant": "base", "boss": false, "maxHp": 815 },
  "wave": 2,
  "result": { "killed": true, "timeMs": 14950, "points": 815, "swings": 12, "maxCombo": 12, "finisher": null }
}
```

| 項目 | 中身 |
|---|---|
| `frames` | 1コマ＝`[時刻ms, x, y, x, y, …]`。鼻・肩・肘・手首・腰・膝・足首の13点。カメラの絵の中の位置（0〜1、鏡にしていない）。見えない点は −1。1秒に15コマ |
| `events` | `[時刻ms, "swing", 型のid, ダメージ, コンボ数]`。通った振りだけ |
| `kind` | `fight`（戦いの影。自動で残る）か `kata`（影の書庫で録った型の見本） |
| `master` | 師範の影の印（影の書庫で録る時にチェックを入れる） |
| `starred` `imported` | 残す印、ほかの人から読み込んだ印 |
| `result.timeMs` | **その妖怪を倒すのにかかった時間**（戦闘の始まりから倒すまで。アプリが裏に回っていた時間は除く） |

- 録るのは、妖怪退治と登頂で**倒せた戦いだけ**。途中で休んだ戦い、TABATA、型の登録は残らない。
- コマを録るのは戦闘中だけ。ボスのとどめと残心の動きは入っていない（`result.finisher` に種類だけ残る）。
- 自動で残すのは新しい順に50本（`ghost.keep`）。星を付けた影・師範の影・型の見本は消さない。
- 3Dの位置は入っていない（2Dだけ）。3Dの影の試験（`ghost3d.html`）は別の録り方をしている。

#### 1本あたりの大きさ（計算。実測ではない）

1コマ約165バイト、1秒約2.5KB。

| 長さ | 大きさ |
|---|---|
| 通常の妖怪（15秒） | 約40KB |
| ボス（40秒） | 約100KB |
| 3分 | 約450KB |

50本で 2〜5MB。圧縮すれば3〜4分の1になる見込み（数字の並びなので縮みやすい）。

#### 「その人の最高記録の影」をどう決められるか

- **今は決める仕組みが無い。** 「最高」の印も、妖怪ごとの最速の記録も持っていない。
- セーブ（localStorage）に妖怪ごとにあるのは、通算の討伐数（`S.kills`）と、1体での最高得点（`S.bestScore`）だけ。**討伐の速さは、影の中の `result.timeMs` にしか無い。** 影は50本で古い順に消えるので、最速の記録が消えることがある。
- 材料はそろっている。一覧（`ghostStore.list()`）を妖怪の id で絞り、`timeMs` が一番小さい物を選べば決められる。
- **ただし、そのままでは比べられない。** 同じ妖怪でも、敵のHPは進んだ数で変わる（2体めの河童は815、9体めなら1,000を超える）。金色・大将でも変わる。武士部門は位・装具・式神で速くなるが、影に残るのは位と得物だけで、装具と式神は残らない。
- 比べるなら、次のどちらかが要る。
  - 仇討ち用に「同じ妖怪・同じHP・装具なし」の一騎打ちを別に作り、その記録だけを比べる。
  - 速さを「1秒あたりの与ダメ（`maxHp ÷ timeMs`）」に直して比べる。今ある記録を使えるが、コンボの倍率があるので、HPが多い相手ほど数字が良くなる。
- 影を人に渡す方法は、ファイルの書き出しと読み込みだけ（影の書庫）。サーバーが無いので、他人の影が自動で届くことは無い。

## 2. 連携データの実際の形

### 置き場と鍵

| 項目 | 中身 |
|---|---|
| 置き場 | ブラウザの localStorage（本体と同じ `hizashi001.github.io` の中だけで共有できる） |
| 鍵の名前 | **`ghost-renkei.v1`**（本体のセーブ `suburi-bugeicho.v1` とは別の鍵） |
| 出入口 | **`js/renkei.js`**（本体も旅も、この部品を通して読み書きする。鍵を直接さわらない） |
| 数値 | `config/balance.json` の `shugyo`（修行点と倍率）と `kiwami`（試練） |

- 鍵を分けた理由：本体はセーブを丸ごと上書きする。同じ鍵に旅が書くと、本体が開いている間に書いた分が消える。
- 中は2つに分かれている。`hontai` は本体だけが書き、`tabi` は旅だけが書く。書く前に毎回読み直すので、2つのページを同時に開いていても相手の分を消さない。
- 旅のページは `tabi/page/` に置けば、`import * as renkei from "../../js/renkei.js"` で同じ部品を使える（アーティファクトのままでは読めない。質問11）。

### 極みの試練の試作（B3）

- 技は `config/balance.json` の `kiwami.trials` に置く。試作は1本：**「試作・袈裟袈裟胴」＝ 袈裟 → 袈裟 → 胴、間は1秒以内、基準は三段（すべて仮）。**
- 入口は表紙の「極みの試練（試作）」。技と判定の段階を選んで「挑む」。コードでは `startTrial(技, 段階)`。**段階は引数で渡すので、設定の難易度とは別に決められる。**
- **`judge` は変えていない。** `judge` が返す測った値（速さ・向きの差・振り幅・ぶれ・減速）を、試練の側で、指定した段階の門（`judge.levels[n]`）と比べ直している。
- **基本の型を9つとも登録していないと挑めない**（回答5）。登録が残っていると、「挑む」を押した時にその数を出して、型の登録の画面へ移る（`kiwami.needAllForms`）。
- **突きが入った技は一覧に出さない**（回答6。`kiwami.excludeForms`）。旅から渡された技も同じ。
- 流れ：構えの10秒 → 並びの順に振る。
  - 指定した段階の門に届かない振りは、戦闘と同じく見送る（やり直しにはしない。間の時計は進む）。
  - 型が違う、または間が上限を超えたら「失敗」で最初から。間は「前の振りの終わりから、次の振りの始まりまで」。遅れた振りが1振りめの型なら、それを新しい1振りめに数える。
  - 失敗が3回（`kiwami.maxMiss`）で不合格。
- 返す結果：

```json
{ "id": "shisaku_kesa_kesa_do", "name_ja": "試作・袈裟袈裟胴", "name_en": "Trial: KESA, KESA, DO", "seq": ["kesa", "kesa", "do"],
  "passed": true, "level": 2, "need": 2, "clean": true, "top": 2, "miss": 0, "demo": true }
```

| 項目 | 中身 |
|---|---|
| `passed` | 合格か |
| `level` | 挑んだ判定の段階（引数） |
| `need` | その技の基準の段階 |
| `clean` | **緩めずに合格**（合格で、`level` が `need` 以上） |
| `top` | 合格した時の全部の振りが通っていた、一番厳しい段階（参考。入門で挑んでも、振りが三段の門を通っていれば 2 になる） |
| `miss` | 失敗の回数 |
| `demo` | 試し振りが混ざったか（混ざると記録にも修行点にも入らない） |

TABATA の1種目（20秒）で倒すのに要る振り数。

| 種目 | 敵のHP | ゆっくり | ふつう | 最短 |
|---|---|---|---|---|
| 1 | 650 | 18 | 11 | 4 |
| 2 | 715 | 19 | 11 | 5 |
| 3 | 780 | 20 | 12 | 5 |
| 4 | 845 | 21 | 13 | 5 |
| 5 | 910 | 22 | 13 | 6 |
| 6 | 975 | 22 | 14 | 6 |

ふつうに振ると11〜14秒で倒れ、残りの時間は待つだけになる（倒した後は次の妖怪が出ない）。20秒を動き続ける作りには、今はなっていない。

#### 実測を取るには

妖怪を倒すたびに、戦闘の長さ（`result.timeMs`）・振り数・最大コンボ・判定の段階・得物が、影の記録として端末に残っている（`killYokai` 1383行）。ヒデキの iPhone で何体か倒した後、影の書庫（`ghost.html`）から書き出したファイルをもらえれば、この表を実測に置き換えられる。

## 5. チャット側への質問

**1〜15 は回答をもらった（6章）。16〜21 は、作って出てきた新しい質問で、まだ答えをもらっていない。**

1. **修行点を数える条件。** カメラ無しの試し振りと試験用のボタンで妖怪を倒せる。修行点は「カメラが動いていて、試し振りではない振りで倒した時だけ」数える形でよいか。TABATA は「その種目で1回以上（または決めた回数以上）振った時だけ」でよいか。回数を決めるなら、いくつか。
2. **妖怪退治の点。** ふつうの人なら TABATA と同じ得さ（1分に約2点）だが、速い人は約3倍得になる。このままでよいか。直すなら、「1日に妖怪退治で入る点の上限」か「倒すのにかかった時間で点を決める」が考えられる。
3. **ボスの点。** ボスは通常の約3倍かかるのに同じ0.8点になる。ボスだけ点を上げるか。とどめ（居合・秘伝）に点を付けるか。
4. **「妖怪1体約3分」との食い違い。** 今の設定値では、ふつうで15〜20秒。本体の側を3分に寄せる予定があるなら、0.8点は大きく変わる。どちらを正とするか。
5. **極みの試練の中身。** 並び・間隔・速さの3つで書ける。間隔は「前の振りの終わりから次の振りの始まりまで」で測るのが今の作りに合う。SPEC の例「それぞれの間は1秒以内」はこの測り方でよいか。速さは「手本（本人が登録した型）に対する割合」になるが、それでよいか。型を登録していない人は標準の値と比べることになる。
6. **突きを試練に入れるか。** 突きは認識されにくい。入れないほうが安全。
7. **判定の段階の名前。** 画面は「入門・初段・三段・師範・神域」。SPEC の「入門〜神域」と合っている。`balance.json` の説明文だけ古い（二段・免許皆伝）。直してよいか。
8. **持ち物の共通化の向き。** 部位（9と10）、等級（5と6）、主性能の種類、式神（1体と3体、顔ぶれ）がどれも違う。どちらに寄せるか、または対応表で読み替えるか。本体の装具は「％だけ・位で伸びない」、旅は「固定値が関で伸びる」ので、そのまま同じ物として使うと旅では弱すぎる。
9. **登頂の装具。** 登頂は「その日に拾った物だけ」で、本体の手持ちとは別に持っている。共通の持ち物に入れるか。
10. **式神の星。** 本体では飾り。旅の「欠片でLv10まで」に読み替えるか。
11. **旅のページの置き場。** アーティファクト（claude.ai）のままでは、本体と端末の中のデータを共有できない。合わせてテストするには、旅のページをリポジトリ（`tabi/page/`）に置く必要がある。今のテストプレイ画面を書き出して渡してもらえるか。置き場はこのままでよいか。
12. **仇討ちの比べ方。** 今の記録は、同じ妖怪でもHPが違い、装具の有無も残っていないので、そのままでは速さを比べられない。「同じ妖怪・同じHP・装具なしの一騎打ち」を仇討ち専用に作る形でよいか。それとも1秒あたりの与ダメで比べるか。
13. **最高記録の影の残し方。** 影は50本で古い順に消える。妖怪ごとの最速の1本を自動で残す（星を付ける）形にしてよいか。妖怪ごとの最速の時間を、セーブにも持たせてよいか。
14. **時刻とサーバー。** SPEC 9.7 の「サーバーの時計」「セーブをサーバーにも置く」は、サーバーが無い今は作れない。連携の試作は端末の時計で進めてよいか。
15. **週替わりの秘伝。** 本体にはまだ無い（仮の1本が固定）。デイリークエストの例「今週の秘伝でとどめ」は、秘伝の週替わりを先に作る必要がある。とどめはボスだけなので、5体めまで進まないと達成できない。
16. **「緩めずに合格」の決め方。** 今は「挑む時に選んだ段階が、技の基準の段階以上」で印を付ける。入門を選んで挑むと、振りが実際は三段の門を通っていても「緩めて合格」になる。これでよいか。それとも、実際の振りが通った段階（結果の `top`）で印を決めるか。技ごとの基準の段階は誰が決めるか（試作は仮に三段）。
17. **試練の失敗と点。** 失敗3回で不合格、門に届かない振りは見送る（やり直しにしない）、合格するたびに1点（同じ技でも入る。不合格は0点）、という仮の形にした。直す所はあるか。試練の点に1日の上限は要るか。
18. **「修行した日」の数え方。** 1点でも入った日を、修行した日（連続日数に数え、休みにしない）としている。これでよいか。決めた点（例：5点）に届かない日は休み扱いにするか。
19. **登頂の数え方。** 登頂で倒した妖怪は「登頂の1階」だけに数え、「妖怪退治の1体」には数えていない。デイリークエストで「妖怪を○体」と出す時、登頂の分も入れたいなら、旅の側で `yokai + climb` と足してほしい。
20. **一騎打ちでそろえる条件。** 妖怪・HP・装具なし・位なし・敵の攻撃は全員同じにした。判定の段階（入門は緩いが得点の倍率が低い、神域は厳しいが倍率が高い。与えるダメージに効く）と、得物の重さ（重いほど一撃が強い）はそろえていない。仇討ちでは、判定の段階を1つに固定するか。得物は階級（軽量・中量・重量）ごとに比べるか。HP の仮の値（通常 1,500、ボス 3,000）はこれでよいか。
21. **仇討ちの相手の影。** 今は相手の「時間」だけを旅から受け取り、それより速ければ成功にしている。相手の影（骨格の記録）を横に並べて戦うなら、影のデータを旅からどう渡すかを決めたい。影は1本で数百KBあり、localStorage には入れにくい。サーバーが無い間は、時間だけの勝負でよいか。
