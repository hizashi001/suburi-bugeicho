## 4. ①持ち上げる（2Dの点 → 3Dの関節の位置）

### 座標

影の点は「カメラの絵の中の位置。x・y は 0〜1、鏡にしていない。z は腰からの奥行きで、カメラ側がマイナス、尺度は x と同じ」（`js/ghost.js`）。**鏡にしない向きで3Dを組み、最後に描いた絵を左右に返す**（こうすると、人の左腕＝モデルの左腕のままで済む。先に鏡にすると、左右の骨を入れ替える必要が出る）。

3Dの空間（単位は「絵の幅」）：

```
X = x − 腰の中点の x        （画面の右がプラス。正面を向いた人の左側がプラス）
Y = −(y − 腰の中点の y) ÷ 縦横比   （上がプラス。縦横比 = 絵の幅 ÷ 高さ。影の aspect）
Z = 手前（見る人の側）がプラス
```

カメラの遠近（近い物が大きく映る）は無視する。「計算で作った影」で測ると、これによるずれは手足の長さの1割ほど。

### 骨の長さ

腕と脚の8本（上腕・前腕・腿・脛の左右）の長さ `L` は、影1本につき1つずつ決める。`createMotion(...).info.lengths` が、`boneLock: "clamp"` の時に「画面の上でその骨がふつうに描かれる一番長い長さ（90パーセンタイル）と、3Dの長さの中央値の、大きい方」を返す（順番は `[左上腕, 左前腕, 右上腕, 右前腕, 左腿, 左脛, 右腿, 右脛]`）。**左右の大きい方を、両方に使う**（体は左右同じ長さ）。

### 関節を順に置く

付け根から先へ、1本ずつ。親の関節の3Dの位置 `A` が決まっていて、子の点の画面の位置 `(Xb, Yb)` が分かっている時：

```
flat = √((Xb − Xa)² + (Yb − Ya)²)        … 画面の上での骨の長さ
dz   = √(max(0, L² − flat²))             … 奥行きの差の「大きさ」。骨の長さが変わらない、から出る
Zb   = Za + sign × dz                    … sign は +1（手前）か −1（奥）
flat > L の時は dz = 0（createMotion が伸びを止めているので、ほぼ起きない）
```

**これが要。奥行きの大きさは、荒い z ではなく、正確な x・y と骨の長さから出る。** 骨が画面とほぼ平行（flat が L に近い）なら dz は小さく、符号を間違えても見た目はほとんど変わらない。骨がカメラへ向いている時（flat が小さい）だけ符号が効く。

### 符号（手前か奥か）の決め方

1. 影の z の差（子 − 親。カメラ側がマイナスなので、**マイナスなら手前＝sign +1**）を、時間でならす（0.25秒）。
2. ならした差が ±`signGap` を超えた時だけ符号を替え、超えるまでは前の符号を保つ（ちらつき止め）。
3. 体の作りで縛る：
   - **膝は前にしか曲がらない。** 脛の符号は、「膝が、腰と足首を結ぶ線より、体の前（腰の線の向きから出す）にある」形になる方を選ぶ。
   - **肘は逆に曲がらない。** 前腕の符号で肘が逆に折れる形になるなら、もう一方を選ぶ。
4. 骨がほぼ画面と平行（`flat > L × 0.92`）の間は、符号を替えない（どちらでも同じに見えるので、雑音で替えない）。

2Dの試作で使った値（`js/shadowstyle.js`。腕・脚ごとに 0.25秒ならし、差が 0.08 を超えたら入れ替え）が出発点。

### 胴と頭

| 部位 | 置き方 |
|---|---|
| 腰の2点 | 画面の位置はそのまま。奥行きは、腰の線の向き（`createMotion(...).metaAt(t).facing.hips`、度）から：左右の差 = 腰幅 × sin(向き)。腰幅は影全体の「画面の上の腰幅」の90パーセンタイル |
| 肩の2点 | 同じ。向きは `facing.shoulders`、肩幅も同じ出し方 |
| 腰の中点 → 肩の中点 | 画面の位置はそのまま。奥行きの差は、胴の長さ（画面の上の長さの90パーセンタイル）から、手足と同じ式。符号は肩の中点と腰の中点の z の差（ならす）。前かがみが出る |
| 頭 | 鼻の点しか無い。第3D-2段では「肩の中点から、背骨の向きへ伸ばした所」に置き、顔は肩の向きに合わせる。**記録に両目・耳を足すと、頭の向きが出せる（第3D-4段）** |

向きの符号：正面が0°、本人の左側がカメラへ寄ると＋、背中は±180°（`js/shadowmotion.js` の `yawOf`）。

### 根の位置と大きさ

- モデルの根（腰）の位置：画面の上の腰の中点（X, Y）を、そのままモデルの位置にする。奥行きは動かさない（前後の歩きは出さない。大きさの変化で出すと、荒くなる）。
- 大きさ：影の「腰の中点〜肩の中点」の長さと、モデルの同じ長さの比で、モデルを拡大縮小する（影ごとに1回決める）。
- 足が床に付くよう、モデルの一番低い足の高さを床にする（`ghost3d.html` の `floorY` と同じ考え）。

### 1コマだけの飛びの手当て（まだ確かめていない案）

前後のコマの真ん中から大きく離れ、前後のコマどうしは近い点を「見えなかった」扱いにすれば消せるが、**画面の上では、速い回転切りの手先と見分けが付かない**（作って外した。`docs/設計_影の見た目.md`）。見分ける案：同じ3コマの間に、**両肩の中点がほとんど動かず（絵の高さの2%未満）、画面の上の肩幅も2割以上変わらない**時だけ、飛びとみなす（本当の回転なら、肩が入れ替わるので肩幅が大きく変わる）。「早い乱撃」の 8.95秒が消え、計算で作った「回転切り」の手先が消えないことを確かめてから入れる。入れる場所は `createMotion` の最初（見えない点を埋める前）。

## 5. ②骨へ移す（3Dの関節の位置 → モデルの骨の回転）

モデルは VRM（`@pixiv/three-vrm` 2.1.2。`ghost3d.html` と同じ版を同じ所から読む）。**Kalidokit は使わない。** 骨を、目当ての向きへ直接向ける。

### 使う骨と、目当ての向き

`vrm.humanoid.getNormalizedBoneNode(名前)` で取る「正規化された骨」を回す。正規化された骨は、Tポーズ（腕を横へ広げた立ち姿）の時に回転が0で、モデルは +Z（見る人の側）を向く。VRM 0 の時は `VRMUtils.rotateVRM0(vrm)` を呼ぶ（`ghost3d.html` の `loadVrm` に書いてある）。

| 骨 | 目当ての向き（3Dの関節から） | Tポーズでの向き |
|---|---|---|
| `hips` | 体の3本の軸：右向き＝右腰→左腰、上向き＝腰の中点→肩の中点、前向き＝その2本に垂直 | 右向き +X（モデルの左が +X）、上 +Y、前 +Z |
| `spine`・`chest` | 腰の軸から肩の軸（右向き＝右肩→左肩）への回転を、半分ずつ分ける。上半身のひねりがここで出る | 同じ |
| `leftUpperArm` | 左肩 → 左肘 | +X |
| `leftLowerArm` | 左肘 → 左手首 | +X |
| `rightUpperArm`・`rightLowerArm` | 右肩 → 右肘、右肘 → 右手首 | −X |
| `leftUpperLeg`・`rightUpperLeg` | 腰 → 膝 | −Y |
| `leftLowerLeg`・`rightLowerLeg` | 膝 → 足首 | −Y |
| `head`・`neck` | 第3D-2段では動かさない（胸に付いて回る）。第3D-4段で向きを足す | － |
| `leftHand`・`rightHand` | 動かさない（前腕の延長のまま） | － |

### 回転の決め方（付け根から先へ）

```
親の骨の、世界での回転を Qp とする（hips から順に決めていく）。
子の骨の Tポーズでの向きを r（上の表）、目当ての向きを d（長さ1）とする。

今の親の回転のままだと、子は Qp·r の向きを向く。
世界での回転   Qw = （Qp·r を d へ回す、一番小さい回転）× Qp
子の骨に入れる回転（親から見た回転） = Qp の逆 × Qw
```

three.js では `new THREE.Quaternion().setFromUnitVectors(Qp·r, d)` が「一番小さい回転」。こうすると、骨の軸まわりの余計なねじれが入らない（腕のねじれは元々分からないので、入れない）。

- 骨に回転を入れた後、`vrm.update(dt)` を呼ぶ（揺れ骨が動く）。`dt` は再生の時間の進み。一時停止とコマ送りの時は 0。頭出しの時は、揺れ骨を置き直す（`vrm.springBoneManager?.reset()`）。
- **最初に必ず確かめる：** 計算で作った影（`tools/test/ghosts/calc_*.ghost.json`）は推し間違いが無い。「ゆっくりの型」で、構え・上段・振り下ろしの腕が、左の骨格の表示と同じ形になること。合わない時は、上の表の Tポーズの向き（±X）を疑う（モデルの向きが逆だと、左右と前後が逆になる）。`ghost3d.html` の「向きの補正」ボタンは Kalidokit のための物で、この方式では要らないはず。

## 6. ③描く

| 項目 | やり方 |
|---|---|
| 読み込み | 試験場で描き方「3D」を選んだ時に、`import("./js/shadow3d.js")` で初めて読む。three.js は `ghost3d.html` の `importmap` と同じ版（three 0.164.1、three-vrm 2.1.2）。`shadowlab.html` にも同じ `importmap` を足す（Kalidokit の行は要らない） |
| キャンバス | WebGL のキャンバスを画面の外に1枚持ち、そこへ描いてから、試験場の2Dのキャンバスへ `ctx.drawImage()` で写す。**写す時に左右を返す**（`ctx.scale(-1, 1)`。ほかの描き方が `1 - x` で鏡にしているのと合わせる）。背景は透明（`alpha: true`、`setClearColor(0, 0)`） |
| カメラ | 正面から、まっすぐ（平行投影 `OrthographicCamera`。影の絵の枠＝カメラの絵の枠に合わせる）。こうすると、3Dの体が、元の骨格の点と同じ場所に重なる |
| 体 | 真っ黒＋縁の光。`ghost3d.html` の `ghostify()`（視線に対して斜めの面ほど光る）がそのまま使える。**全周ではなく片側だけ光らせる**には、光の向き（画面の左上）と面の向きの内積を掛ける |
| 呼び方 | ほかの描き方と同じ `draw(ctx, pose, box, { aspect, t, meta, ghost })`。試験場の `RENDERERS` に `{ id: "vrm", make: (g) => … }` を1行、文言 `slab.r.vrm` を ja/en に足す。動きは「整える」で見る（`meta` が来る） |
| 刀 | 第3D-2段では、今と同じ「前腕の延長」に細い板を置く。向きは当たらない（測った：真ん中の値で 64° ずれる） |
| 数値 | `config/balance.json` の `shadow.d3`（新しく作る）。`_note` に日本語で意味を書く。最初の値：`model: "assets/models/shadow.vrm"`、`signGap: 0.08`、`signEaseSec: 0.25`、`flatHold: 0.92`、`rim: 1.4`、`pixelRatio: 1.5` |

## 7. 段の順番と、できたと言える条件

**1回のセッションで1段。** 各段の終わりにコミットし、push はヒデキの了承を取ってから。

| 段 | 作る物 | できたと言える条件 |
|---|---|---|
| 3D-1 持ち上げる | `js/shadow3d.js` に `createLift(ghost, motion, cfg)`。`lift.at(t)` が13点の3Dの位置を返す。試験場に、3Dの棒の人を**横から見た絵**で出す描き方（2Dのキャンバスに X を Z に替えて描くだけ。three.js は要らない） | 計算の影4本で、横から見た形が元の動き（`tools/test/mkghosts.py` の式）と合う。「早い乱撃」で、止まっている間に手足が前後に暴れない。腕と脚の長さがどのコマでも変わらない（測って数字で出す） |
| 3D-2 骨へ移す・描く | `shadow3d.js` に VRM の読み込み、骨の回転、描く所。試験場の描き方「3D」。今ある `shadow.vrm` を使う | 計算の「ゆっくりの型」で、腕の形が骨格の表示と合う。「回転切り」で1回転し、背中が見える。「早い乱撃」を通して再生し、赤い枠が出ない。描く時間が試験場に出る |
| 3D-3 ヒデキが見る | push して、ヒデキが公開ページと iPhone で、今の影絵と並べて見る | **動きが見られる水準か、ヒデキが決める。** 良ければ 3D-4 以降と、モデル作り（8章）へ。だめなら9章 |
| 3D-4 点を増やす | 記録する点に、両目・両耳（2・5・7・8）と、かかと・つま先（29〜32）を足す。頭の向きと足先の向きを出す | 新しく録った影で、頭が顔の向きに回り、足先が向く。古い影（13点）もそのまま再生できる |
| 3D-5 本物のモデル | ヒデキのモデルを読む。袴・袖・髪の揺れ骨。影ごとの色 | 「早い乱撃」と回転切りで、袴が脚を突き抜けない。揺れが暴れない |
| 3D-6 重さと組み込み | iPhone で測る。影の書庫（`ghost.html`）の再生を3Dに。重い端末は今の影絵に落とす | iPhone で、影の書庫の再生が1秒30コマ。戦闘中（骨格推定と同時）に入れるかは、測ってから決める |

第3D-4段の注意：記録の形は `ghost/1` のまま。`points` に番号を足すだけなので、点を番号で引く読み手（`poseAt`、`createMotion`、今の影絵）はそのまま動くはず。**足す前に、点を「13個」と決め打ちしている所が無いか、`index.html`・`ghost.html`・`js/ghost.js` を調べる。** ファイルは約1.6倍になる。

## 8. ヒデキが作るモデルの決まり（下書き。3D-3 の後で、1枚にして渡す）

| 項目 | 決まり | 理由 |
|---|---|---|
| 形式 | VRM 1.0（VRoid Studio から書き出すか、Blender の VRM アドオン）。人型の骨（Humanoid）が入っていること | 骨の名前がそろっているので、モデルを替えてもコードを変えずに済む |
| 姿勢 | Tポーズ（腕を真横）。+Z 向き（VRM の決まりどおり） | 5章の計算の前提 |
| 面の数 | 3万三角形くらいまで。布（袴・袖）を含めて | iPhone で、骨格推定と同時に動かす余地を残す。測ってはいない |
| 模様の画像 | 無くてよい（影は黒で塗り替える）。あっても 1024×1024 を1〜2枚まで | 今の `shadow.vrm` は 9.5MB で、ほとんどが模様の画像 |
| 形で見せる | 髷、肩衣、袖、袴、帯、刀の鞘。**輪郭に出ない細工は見えない** | 影は黒いシルエットで見せる |
| 袴 | 脚の骨に貼り付けない。腰から下がる布として、揺れ骨（VRM の SpringBone）で動かすか、前後左右4枚ほどの硬い板にして腰に付ける | 脚と一緒に曲がると、股が裂けて見える。3Dで一番難しい所 |
| 袖・髪・帯の端 | 揺れ骨を入れる | 動きの遅れと余韻が、ここで出る |
| 刀 | 体とは別の物にする（手の骨に付けない） | 刀の向きは、後で「刀を見つけるAI」の結果で別に動かす |
| 権利 | 自作か、商用とアプリへの組み込みが許された物。VRM の中の利用条件も合わせる | 公開のリポジトリに置く |

忍のモデルは、侍が通ってから。

## 10. 守ること（`CLAUDE.md` と同じ）
