# 設計：影の見た目を上げる（手順つき）

2026-11-16 作成。ヒデキが出した参考の動画（影の戦士が戦う、他社ゲームの広告。22秒）の水準に、プレイヤーごとの影を近づけるための設計と、作る順番。

- この資料だけで、新しいセッション（Opus でも可）が1段ずつ進められるように書いた。始め方は最後の章。
- **参考の動画は「どこまでの見た目を目指すか」の基準にするだけ。** そのゲームのキャラクター・絵・構図は写さない。影の姿は、このアプリの侍・忍・鬼面・刀で作る。
- この資料は設計で、まだ何も作っていない。数字（コマ数、重さ）は見込みで、iPhone で測った値ではない。

---

## 1. 参考の動画は、何で良く見えているか

動画を0.5秒ごとのコマにして見た。良く見える理由は7つに分けられる。

| # | 要素 | 動画でのやり方 |
|---|---|---|
| 1 | **形** | 体はほぼ真っ黒。それでも誰か分かるのは、輪郭に特徴があるから（角、帽子、髪の束、裾の切れ込み、武器）。丸と棒ではなく、描かれた形 |
| 2 | **差し色** | 黒の中に、光る所が少しだけある（目、面、帯、武器の芯）。色は1体につき1〜2色 |
| 3 | **縁の光** | 体の片側の縁だけが、背景や技の色で細く光る。全周ではない。これで立体に見える |
| 4 | **揺れる物** | 髪、袖、裾、帯が、体より遅れて動く。止まった後も少し揺れる |
| 5 | **技の絵** | 炎、煙、光の輪、火の粉、地面の光の輪。何枚も重ね、明るい所は白く飛ぶ。当たる瞬間に画面全体が1〜2コマ光る |
| 6 | **舞台** | 描き込んだ背景。色は1場面1系統（赤、紫、緑）で、キャラクターの差し色と同じ。奥・中・手前の層がある |
| 7 | **間** | 溜め → 一気に動く → 止まる。場面の切り替えは、色の面が画面を横切る |

**作りは2Dの切り絵の人形**（部品の絵を骨に付けて動かす）と見てよい。3Dではない。

## 2. 今の影と、足りないもの

| 要素 | 今の作り | 足りないもの |
|---|---|---|
| 形 | `js/ghost.js` の `createGhostRenderer`。骨格13点から、丸と太い線と多角形で侍を描く | 描かれた形。人ごとの違い |
| 差し色 | 無い（全身が黒） | 目、面、帯、刃 |
| 縁の光 | 全周を同じ色でぼかす（オーラ）と、全周の細い縁 | 片側だけの光。背景の色と合わせること |
| 揺れる物 | 無い | 髷、袖、袴の裾、帯 |
| 技の絵 | 刀の残光（線）、立ちのぼる火の粉 | 斬撃の弧、煙、地面の輪、当たりの光 |
| 舞台 | 無い（カメラの映像か、暗い背景） | 背景の絵、霧、色の統一 |
| 間 | 本体にヒットストップとスローがある | 影の再生の側には無い |
| 動きの元 | 骨格推定。記録は1秒15コマ、2Dの13点 | 震えの除去、コマの間の補い、体の向き |

3Dの試験（`ghost3d.html`、VRM）は「可能性は見えるが、まだまだ」（ヒデキ、`docs/引継ぎ_全体.md`）。

**一番の違いは動きの元。** 動画は人が1コマずつ決めた動き。こちらは、1台のスマホが推した骨格で、震えるし、隠れた手足は飛ぶ。絵だけ良くしても、動きが震えていれば安く見える。だから、絵より先に動きを整える（第1段）。

## 3. 方針：2Dの切り絵の人形にする

**すすめる道：2Dの切り絵の人形を主にする。3D（VRM）は試験のまま置く。**

| 比べる点 | 2Dの切り絵の人形 | 3D（今の試験） |
|---|---|---|
| 参考の動画との近さ | 同じ作り。近づけやすい | 違う作り。影絵の味を出すには別の工夫が要る |
| 体の向き | 真っ黒なので、前か後ろかが目立たない。腕や脚がカメラ側へ向いた時は、部品を縮めれば済む | 向きは正確に出るが、骨格の奥行きが不正確だと破綻が目立つ |
| 絵の用意 | 部品の絵を10〜20枚。ヒデキが今の画像生成で作れる | 侍の3Dモデルが要る。袴の扱いが難しい |
| 重さ | 軽い。骨格推定と同時に動かせる見込み | 重い。iPhone で骨格推定と同時は厳しい見込み |
| 人ごとの違い | 部品の差し替え（鬼面、被り物、刀、陣羽織）と色 | モデルの差し替えが重い |
| `CLAUDE.md` との関係 | 「影絵の部品画像を骨格に付ける形にする」と書いてある方向 | 「3Dアバターは作らない」の見直しが要る |

弱い所：真横を向いた時と、体をひねった時。部品を「正面用」「横用」の2組にして切り替えることで補う（第2段）。

**ヒデキの答え（2026-11-16）：回転切りやひねりに対応できるなら、この方針でよい。** 対応できるかは、ヒデキの写真で確かめた（9章）。答えは「できる。ただし条件が3つある」。

### プレイヤーごとの違いは、何で出すか

| 違い | 元になる物 | いつ |
|---|---|---|
| 動き | 本人の骨格の記録（今ある） | 今 |
| 色（縁の光・差し色） | 影の色。師範は金、ほかは青（今ある）。後で称号や戦績で増やす | 第5段 |
| 顔 | 鬼面。`data/masks.json` に目の位置がそろっている。黒い影に面だけ色が乗る | 第3段 |
| 被り物・羽織 | `assets/ghost_asset_manifest.json` の `shadow_part_*`（陣笠・兜・編笠・頭巾・鉢巻・陣羽織。絵はまだ無い） | 第3段 |
| 刀 | 得物の種類（刀・短刀）、名物の刀なら刃の光の色 | 第3段・第6段 |
| 体つき | 身長と肩幅（骨格から出る） | 第2段 |

## 4. 全体の順番

上から順に進める。**各段の終わりに、ヒデキが iPhone で見て、次へ進むかを決める。**

| 段 | 作るもの | 終わりの目安 | 絵が要るか |
|---|---|---|---|
| 0 | 比べる場（試験ページ）と、基準の影 | 同じ影を、古い描き方と新しい描き方で並べて見られる | 要らない |
| 1 | 動きを整える | 止まっている時に震えない。速い振りで手足が飛ばない。60コマで滑らかに見える | 要らない |
| 2 | 人形の骨組み（部品は仮の形） | 仮の部品の人形が、基準の影で破綻なく動く。横向きでも崩れない | 要らない |
| 3 | 部品の絵 | 侍と忍の2体が、描かれた形で動く。鬼面が付く | **要る** |
| 4 | 揺れる物 | 髷・袖・裾・帯が遅れて動き、止まった後に揺れる | 少し要る |
| 5 | 光 | 片側の縁の光、目と刃の光、光のにじみ、足元の光 | 要らない |
| 6 | 技の絵 | 斬撃の弧、火の粉、煙、当たりの光、とどめの地面の輪 | **要る** |
| 7 | 舞台 | 背景3層、霧、色の統一、カメラの寄りと揺れ | **要る** |
| 8 | 決め場面 | とどめの止め絵、色の面の切り替え、縦動画への書き出し | 要らない |
| 9 | 本体への組み込みと重さの調整 | 妖怪退治・影の書庫・シェアが新しい影で動く。iPhone で骨格推定と同時に1秒30コマ | 要らない |

絵が無くても進められるのは 0・1・2・5・8・9。絵を待つ間は、そちらを先に進める。

## 5. 各段の中身

どの段も、次の決まりを守る（`CLAUDE.md` と同じ）。

- 振りの判定（`judge`）と判定の値は変えない。
- 数値は `config/balance.json` に置く。置き場は新しく `shadow` を作り、`_note` に日本語で意味を書く。
- 画面の文言は `lang/ja.json` と `lang/en.json` の両方に入れる（`python tools/test/keys.py` で抜けを確かめる）。
- iPhone で確かめていないことを「動く」と言わない。
- 映像は端末の外に出さない。影は骨格のデータだけ。

### 第0段：比べる場を作る

**目的：** 良くなったかどうかを、毎回同じ材料で見比べられるようにする。これが無いと、直しても良くなったか分からない。

| 作るもの | 中身 |
|---|---|
| 影の記録に奥行きを足す | `js/ghost.js` の記録に、点ごとの奥行き（骨格推定の z）を足す。古い影（奥行き無し）も読めるままにする。**基準の影を録る前に、これを先に入れる**（9章の条件1） |
| `shadowlab.html` | 影のファイル（`.ghost.json`）を読み、左に今の描き方（`createGhostRenderer`）、右に新しい描き方で、同じ時刻を並べて再生するページ。再生・一時停止・コマ送り・0.25倍速。1秒のコマ数と、1コマを描くのにかかった時間を出す |
| 基準の影4本 | ①ゆっくりの型（構え→真向→残心）、②速い連撃（袈裟→逆袈裟→胴を続けて）、③ひねり（横を向く、上半身だけひねる）、④回転切り（1回転）。ヒデキが iPhone の影の書庫（`ghost.html`）で録って書き出す。**`swordlab.html` の写真（刀の学習用）ではなく、影の書庫の「影を録る」で録る**（1秒15コマの骨格。写真は入らない） |
| 背景の切り替え | 黒・濃い藍・明るい灰の3つ。黒い影は、明るい背景で粗が見える |

- **できたと言える条件：** 基準の影を読み込んで、左右に並んで再生できる。コマ数が出る。
- **確認1つ：** 基準の影を、リポジトリ（公開）の `tools/test/ghosts/` に置いてよいか。中身は骨格の点だけで、顔も映像も入っていないが、ヒデキ本人の動き。置かないなら、ヒデキの手元に置き、試験ページで毎回読み込む。

### 第1段：動きを整える

**目的：** 震えと飛びを消す。絵に入る前にやる。効果が一番大きい。

| 手当て | やり方 | 設定の名前（案） |
|---|---|---|
| 震えを取る | 点ごとに、遅い時は強くならし、速い時はならさないフィルタ（One Euro フィルタ）。止まっている時だけ効き、振りは遅れない | `shadow.smooth.minCutoff` `shadow.smooth.beta` |
| コマの間を補う | 記録は1秒15コマ。再生は60コマで、前後のコマをなめらかな曲線（Catmull-Rom）でつなぐ。今は直線 | `shadow.interp` |
| 骨の長さをそろえる | 上腕・前腕・腿・脛の長さは、その影の中央値に固定する。推定がぶれて腕が伸び縮みするのを止める。カメラ側へ向いた時の縮みだけは残す | `shadow.boneLock` |
| 見えない点の扱い | 見えなかった点（記録では -1 が入っている）は、直前の向きを保って、見えた時にゆっくり戻す。いきなり飛ばさない | `shadow.holdMs` |
| 足を地面に付ける | 足首の高さがほぼ動かない間は、足の位置を止める。滑って見えるのを防ぐ | `shadow.footLock` |
| 体の向きを出す | 左右の肩の幅（体の長さに対する割合）から、正面・斜め・横を出す。第2段で使う | `shadow.facing` |

- 置き場：`js/shadowmotion.js`（新しく作る）。入力は影のファイルと時刻、出力は整えた13点と、体の向き。**描き方とは切り離す**（今の描き方にも、新しい人形にも使える）。
- 記録のコマ数を15から30へ上げる案もある。ファイルは約2倍になる。上の「間を補う」を先に試し、足りなければ上げる。上げるなら `balance.json` の `ghost.fps`。
- **できたと言える条件：** `shadowlab.html` で、整える前と後を並べて見て、①で止まっている時に震えない、②で手先が飛ばない、③と④で腕の長さが変わらない。ヒデキが見て良しとする。
- **やらないこと：** 振りの切り出しや判定に使う骨格は触らない。整えるのは「見せる側」だけ。

**確認1つ（決めたいこと）：型への寄せ。** 振りが通った瞬間だけ、姿勢を登録した型の手本へ少し寄せる、という手当てもできる（その振りがどの型かは、影に記録している）。見栄えは上がるが、「本人の動きそのまま」ではなくなる。やるか、やらないか、やるなら何割までか。

### 第2段：人形の骨組み

**目的：** 部品の絵を骨に付けて動かす仕組みを作る。絵が無くても進められるよう、部品は仮の形（プログラムで描いた黒い形）で始める。

**部品の一覧（1体ぶん）：**

| 部品 | 付く骨（骨格の点） | 備考 |
|---|---|---|
| 頭 | 鼻、両肩の中点 | 鬼面・被り物はこの上に重ねる |
| 胴（上） | 両肩 → 両腰 | 着物の襟、肩の張り |
| 上腕 左・右 | 肩 → 肘 | |
| 前腕 左・右 | 肘 → 手首 | 袖は第4段で揺らす |
| 手 左・右 | 手首 | 柄を握る |
| 袴 左・右 | 腰 → 膝 → 足首 | 脚ごとに1枚ずつ。真ん中は胴の下端で隠す |
| 足 左・右 | 足首 | |
| 刀 | 両手首 → 刀の向き | 向きは今と同じ出し方（前腕の延長）。刀を見つけるAI（`docs/引継ぎ_刀検出AI.md`）ができたら差し替える |
| 髷・髪 | 頭 | 第4段で揺らす |
| 帯・羽織 | 腰・肩 | 第4段で揺らす |

**決めること：**

| 項目 | 決め方 |
|---|---|
| 部品の定義 | `data/shadow_rig.json`。部品ごとに、絵のファイル名、付け根の点（絵の中の座標）、先の点、太さの基準、重ねる順 |
| 伸び縮み | 部品は、付け根から先までの長さに合わせて縦に伸び縮みさせる。カメラ側へ向いて短く見える時は縮む。縮みすぎる時（半分以下）は、丸い「断面」の部品に切り替える |
| 関節のつなぎ目 | 部品の端を丸くし、少し重ねる。肘と膝に丸い当て布の部品を置く |
| 体の向き | 第1段の向きで、部品の組を切り替える。絵は正面用と横用の2組。**向きは「正面・横・背中」の3つを見分ける。** 背中は正面用の絵を使い、顔（鬼面・目）を隠して、髷を手前に描く。真っ黒なので、正面と背中は同じ輪郭で足りる。切り替えの時は2〜3コマかけて入れ替える |
| ひねり | 胴は1枚の固い絵にしない。**肩の線と腰の線を結ぶ四角形として、毎コマ形を変える。** 肩と腰は別々に向きを持つので、上半身だけひねった形がそのまま出る。横を向いて線が短くなった時は、体の厚みぶんの幅を残す（線1本に潰さない） |
| 背を向けた間の腕と刀 | カメラから見えないので、骨格は当て推量になる（9章）。見えなくなる直前の形を保ち、見えた時の形へなめらかにつなぐ。布の流れ（第4段）と刃の残光で覆う |
| 重ねる順 | 正面：奥の腕 → 胴 → 袴 → 頭 → 手前の腕 → 刀。横：奥の腕と脚 → 胴 → 手前の脚 → 頭 → 手前の腕。どちらの腕が手前かは、肩と手首の奥行きで決める |
| 描く道具 | WebGL（three.js の平面。`ghost3d.html` で読み込み済み）。Canvas 2D でも動くが、第5段の光が重くなる。**第2段は Canvas 2D で始め、第5段で WebGL に移すかを重さで決める** |

- 置き場：`js/shadowpuppet.js`（新しく作る）。`createGhostRenderer` と同じ呼び方（`draw(ctx, pose, box, ...)`）にして、差し替えられるようにする。古い描き方は消さない（重い端末用に残す）。
- 奥行き：今の記録は2Dの13点だけ（1コマは「時刻、x、y、x、y…」。`js/ghost.js`）。どちらの腕が手前かを出すには奥行きが要る。記録に奥行き（骨格推定の z）の列を足す。古い影（奥行き無し）も読めるようにし、その時は「利き手の側が手前」と決め打ちする。
- **できたと言える条件：** 仮の部品の人形が、基準の影で、関節が離れず、重ねる順が合い、③のひねりと横向きで崩れない。**加えて、回転切り（1回転）と、上半身のひねりの影で崩れないこと。これを通るまで、部品の絵（第3段）は作り始めない。**
- 回転切りの影は、ヒデキの記録のほかに、計算で作った物も使う（骨格を機械的に1回転させた影。カメラの推し間違いが入らないので、描き方だけの良し悪しが分かる）。
- もしここで通らなければ、部品の絵を板として奥行きのある空間に並べる形（2.5D）へ切り替える。部品の絵の決まりは同じなので、絵は無駄にならない。

### 第3段：部品の絵

**目的：** 仮の形を、描かれた形に替える。ここで見た目が大きく変わる。**ヒデキの絵作りが要る。**

**絵の決まり（作る前に、この表を絵を作るチャットへ渡す）：**

| 項目 | 決まり |
|---|---|
| 向き | 部品はまっすぐ縦に置く（付け根が上、先が下）。腕も脚も刀も縦 |
| 大きさ | 1部品 512×1024 まで。使う時は縮める |
| 色 | 体は黒一色に近く（真っ黒〜濃い藍）。**光らせたい所だけ、決めた1色（純粋な赤 `#ff0000`）で塗る。** アプリの側で、赤を影の色に置き換える |
| 輪郭 | 特徴を輪郭で出す。袖の切れ込み、肩の張り、髷、裾のぎざぎざ。中の線は少なく |
| 背景 | 白。使う前に背景を抜く（`CLAUDE.md` の今のやり方） |
| 組 | 正面用と横用の2組。侍（刀）と忍（短刀）の2体 |
| 名前 | `shadow_rig_{samurai|shinobi}_{front|side}_{部品}.png`。置き場は `assets/images/shadow/` |

- 鬼面：`data/masks.json` の目の位置で、頭の部品の上に重ねる。面は元の色のまま（黒い体の中で、面だけ色が乗る）。
- 被り物・陣羽織：manifest の `shadow_part_*`。頭と胴の上に重ねる部品として、同じ決まりで作る。
- 取り込みの道具：背景抜き・縮小・`shadow_rig.json` の付け根の点の入力。付け根の点は、試験ページで絵をタップして決められるようにする（数字を手で打たない）。
- **できたと言える条件：** 侍と忍が、基準の影で、描かれた形で動く。関節のつなぎ目が目立たない。鬼面が顔に付く。明るい灰の背景で見ても粗が無い。
- **絵を待つ間：** 第5段（光）を先に進めてよい。仮の部品でも光は作れる。

### 第4段：揺れる物

**目的：** 体より遅れて動き、止まった後に揺れる物を足す。「生きている」ように見える。

| 物 | 付け根 | やり方 |
|---|---|---|
| 髷・髪の束 | 頭の後ろ | 3〜4節の鎖。節ごとに、前の節を追い、重力で垂れ、少し跳ね返る（ばねの計算） |
| 袖 | 肘と手首 | 手首から垂れる三角の布。2節 |
| 袴の裾 | 足首 | 裾の角が、足より遅れて動く。1〜2節 |
| 帯の端・鉢巻 | 腰・頭 | 細い布。4〜5節 |

- 置き場：`js/shadowpuppet.js` の中。数値（重さ、戻る強さ、止まる速さ）は `balance.json` の `shadow.cloth`。
- 速い振りの時は、布が体の後ろへ大きく流れる。上限を付ける（体の幅の2倍まで）。
- **できたと言える条件：** ②の速い連撃で髪と袖が流れ、①の残心で止まった後に1秒ほど揺れて収まる。暴れない。

### 第5段：光

**目的：** 黒い形を立体に見せる。参考の動画の「片側の縁の光」「目と刃の光」。

| 光 | やり方 |
|---|---|
| 片側の縁の光 | 影の形を、光の来る向きへ少しずらして重ね、はみ出た所だけを色で塗る。全周ではなく片側。光の向きは、舞台（第7段）か、直前の技の絵（第6段）の位置で決める。無ければ斜め上 |
| 差し色 | 絵の赤い所を影の色で光らせる。呼吸のようにゆっくり明滅 |
| 目 | 鬼面が無い影は、頭に細い光の目を2つ。振りの時に尾を引く |
| 刃 | 刃の縁に細い光。速いほど明るい |
| 光のにじみ | 明るい所だけを、にじませて重ねる（bloom）。`ghost3d.html` のやり方が使える |
| 足元 | 足元に、影の色の薄い光の楕円。地面に立って見える |
| 立ちのぼる靄 | 体の縁から、暗い靄が上へ流れる。今の火の粉の代わりに、形のある靄の絵を使う |

- ここで、描く道具を WebGL に移すかを決める。**目安：iPhone で、骨格推定と同時に、影1体を1秒30コマで描けること。** Canvas 2D でこれを割るなら移す。
- 重い端末用に、光を減らした段階を3つ用意する（高・中・低）。`shadow.quality`。
- **できたと言える条件：** 黒い背景でも明るい背景でも、影が立体に見える。影の色を青・金・赤に替えて、どれも破綻しない。コマ数が目安を満たす。

### 第6段：技の絵

**目的：** 振り・当たり・とどめに、形のある光と煙を付ける。**絵作りが要る。**

影の記録には、振りの出来事（時刻、型、与えたダメージ、コンボ数）が入っている（`events`）。これに合わせて出す。

| 出来事 | 絵 |
|---|---|
| 振り | 刃の通った跡に、弧の形の光（帯の形の面に、筆の跡の絵を貼る）。型ごとに向きが違う。速いほど長く明るい |
| S の振り | 弧が太く、白く飛ぶ。1〜2コマ、画面全体がうっすら光る |
| 当たり | 当たった所に、火花と短い光の線 |
| コンボ | 続くほど、体の周りの靄が濃く、色が明るくなる |
| 技（WORKOUTコンボ）・秘伝 | 技名と一緒に、地面に光の輪が広がる |
| とどめ | 大きな弧、遅れて煙、地面の輪。残心の間は、靄がゆっくり収まる |
| 居合 | 抜く前に、足元へ光が集まる。抜いた後に、横一文字の線が残って消える |

- 絵の形：続きコマを1枚に並べた画像（例：8×8コマ、1コマ256×256）。明るい所を足して重ねる。色は白で作り、アプリの側で影の色を付ける。
- 絵の一覧と名前（`fx_slash_01.png` など）は、この段の最初に `docs/` へ1枚にまとめ、ヒデキへ渡す。
- 侍の旅の VFX（`ghost_vfx_src.zip`）はドット絵なので、ここでは使わない。
- 血や流血の表現はしない（`CLAUDE.md`）。火花・光・煙・墨のしぶきで見せる。
- **できたと言える条件：** ②の連撃で、振りごとに弧が出て、向きが振りと合っている。絵を全部出しても、コマ数が目安を満たす。

### 第7段：舞台

**目的：** 影を置く場所を作る。参考の動画で一番「高く」見せているのはここ。**絵作りが要る。**

| 項目 | 中身 |
|---|---|
| 背景 | 1場面につき3層（奥・中・手前）。縦長。色は1系統。場面の案：竹林の夜、燃える城下、月の石段、雪の社 |
| 色の統一 | 場面ごとに、主の色を1つ決める。縁の光と霧は、その色にする。影の色（青・金）は差し色として残す |
| 霧・煙 | 足元と奥に、ゆっくり流れる霧の層 |
| 手前の物 | 画面の端に、手前の草や柱のぼけた影。奥行きが出る |
| カメラ | とどめで少し寄る。当たりで小さく揺れる。ゆっくり呼吸するように拡大縮小 |
| 周辺 | 画面の四隅を暗くする |

- カメラの映像の上に影を重ねる場面（戦闘中）と、背景の絵の上に影を置く場面（影の書庫の再生、シェア動画、影との対戦の結果）を分ける。**戦闘中は、自分の姿が見えることが大事なので、舞台は使わない。**
- **できたと言える条件：** 影の書庫の再生で、背景の上の影が「一枚の絵」に見える。色がばらばらでない。

### 第8段：決め場面

**目的：** 見せ場を作り、縦の動画にして出せるようにする。`docs/設計_シェアと影.md` の④と同じ作業。

| 項目 | 中身 |
|---|---|
| 止め絵 | とどめの瞬間に、0.3秒ほど時間を止め、影を大きく、背景を単色にする |
| 切り替え | 場面の変わり目に、色の面が画面を斜めに横切る（参考の動画の間の取り方） |
| 順番 | 構え（1秒）→ 一番良い連撃（3〜5秒）→ とどめ（止め絵）→ 残心（2秒）→ 結果の文字 |
| 書き出し | 10〜15秒の縦動画。`share.html` の録画の仕組み（キャンバスの録画）を使う |

- 場面は、影の `events` から自動で選ぶ（一番ダメージの大きい連撃、とどめ）。
- **できたと言える条件：** 影1本から、手を入れずに、10〜15秒の縦動画が1本できる。iPhone で共有できる。

### 第9段：本体への組み込みと、重さの調整

| 場所 | 入れ方 |
|---|---|
| 影の書庫（`ghost.html`） | 再生を新しい影にする。舞台あり |
| 妖怪退治・登頂（`index.html`） | 影との対戦で、相手の影を新しい描き方にする。舞台なし、光は「中」 |
| シェア（`share.html`） | 決め場面の動画 |
| 一騎打ち・仇討ち | 最速の影の再生 |

- 重さの目安：iPhone で、骨格推定と同時に、影1体を1秒30コマ。対戦で影が2体出る時は、光を1段下げる。
- 端末ごとに、最初の数秒でコマ数を測って、段階（高・中・低）を自動で選ぶ。
- 古い描き方（`createGhostRenderer`）は、一番軽い段階として残す。

## 7. 届かない所（正直に）

| 項目 | 理由 | できる手当て |
|---|---|---|
| 動きの切れ | 参考は人が決めた動き。こちらは1台のスマホが推した骨格。指、手首のひねり、刀の本当の向きは取れていない | 第1段。刀を見つけるAI。型への寄せ（確認2） |

| 絵の量 | 参考は1体ごとに専用の絵と技がある | 部品の差し替えと色で、少ない絵から多くの姿を作る |
| 戦闘中の見た目 | 戦闘中はカメラの映像が主で、舞台を使えない | 見せ場は、影の書庫・シェア動画・対戦の結果に集める |

## 9. 回転切りとひねりに、2Dで対応できるか（2026-11-16 に確かめた）

ヒデキが `swordlab.html` で撮った写真（3回の撮影、51枚。「早い袈裟・逆袈裟・胴」「ひねり」「ゆっくり」）から、本体と同じ骨格推定（lite）で骨格を取り出し、仮の切り絵（黒い多角形）を当てて、写真と並べて見た。写真は1秒3枚なので、**形だけを確かめた。動きのなめらかさは確かめていない。回転切りそのものの写真は無かった**（「ひねり」の中に、横向きと背中向きがあった）。写真はリポジトリに入れていない。

**答え：できる。ただし条件が3つある。**

| 分かったこと | 数字 | 設計への反映 |
|---|---|---|
| 体の向きは、奥行きから出る | 肩の向きが、正面で 0°前後、横で −95°・+90°、背中で 147°〜167° と出た | 影の記録に奥行きを足す（今は x と y だけ）。**条件1** |
| 肩幅だけでは、正面と背中を見分けられない | 肩幅÷胴の長さが、正面で 0.55〜0.72、横で 0.08、背中で 0.60。正面と背中が同じになる | 2Dの点だけの古い影は、背中を向く動きに使えない |
| 肩と腰の向きは、別々に出る | 肩と腰の差は、ふつうの振りで 0〜16°、ひねりで最大 23° | 胴を「肩の線と腰の線を結ぶ四角形」にすれば、ひねりの形が出る。**条件2** |
| 横と背中を向くと、腕が見えなくなる | 見え方（0〜1）が、正面で 0.9 前後、横と背中で 0.04〜0.36。51枚のうち1枚は骨格が出なかった | 見えない間は、直前の形を保ってつなぐ。**条件3**。これは3Dにしても同じ（元の骨格が当て推量なので） |
| 仮の切り絵は、正面・斜め・横で崩れなかった | 並べて見た18枚 | 2Dの切り絵で形は追える |
| **刀の向きは、骨格からは出せない** | 今の描き方（前腕の延長）と、写真に付けた刀の印とのずれは、真ん中の値で 64°。両手首を結ぶ線にしても 34° | 刀は、刀を見つけるAI（`docs/引継ぎ_刀検出AI.md`）の結果で描く。それまでは「ずれている」前提で、刃の残光を太くぼかして粗を隠す |

3つの条件：

1. **影の記録に奥行きを足す。** 第0段でやる。基準の影は、これを足してから録る（今の影の書庫で録った影は、背中向きの確認に使えない）。
2. **胴は、肩の線と腰の線を結ぶ四角形にする。** 第2段。
3. **背を向けた間の腕と刀は、推しになる。** 回転切りは速いので、見えない時間は0.2〜0.3秒ほどの見込み。直前の形を保ってつなぎ、布の流れと残光で覆う。ここは「本人の動きそのまま」ではなくなる。

届かない所：カメラに背を向けたまま続ける動き（背中越しの構えを長く保つ、など）は、腕と刀が出ない。2Dでも3Dでも同じ。
