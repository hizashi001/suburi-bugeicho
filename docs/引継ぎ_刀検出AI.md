## 1. 何のためか

アプリ「NINJA SAMURAI WORKOUT: GHOST」は、スマホのカメラで素振りを見て判定する侍の素振りRPG。今は骨格推定（MediaPipe Pose）の**手首の位置だけ**から刀の向きを推しているため、次の問題がある。

- 刀の向き・切っ先の速さが分からない（居合で腰に構えても、刀の向きは見えていない）
- 影（GHOST：プレイヤーの動きの記録を光る影として再生する仕組み）の刀が、本物の刀の動きと合わない

そこで、**カメラの映像から刀の「切っ先」と「柄頭（柄の端）」の位置を見つけるAI**を作る。2点が取れれば刀の線が分かる（鍔の位置も取れればなお良い）。

## 2. 条件（守ること）

| 項目 | 条件 |
| --- | --- |
| 動く場所 | まずiPhoneのSafari（ブラウザ）。後でiPhone・Androidのアプリ（ストア）にする |

| 映像 | **プレイヤーの映像は端末の外に出さない**（決定事項）。判定は端末の中だけで行う。学習用のデータはヒデキ自身の動画から作る |
| 大きさ | モデルのファイルは10MB以下が目安（ブラウザで毎回読むため） |

| 利用規約 | **商用で使えること**。例：Ultralytics YOLO は AGPL-3.0 で、商用でコードを公開しないなら有料の契約が要る。Apache-2.0 / MIT の物（MMPose の RTMPose、YOLOX など）を優先して検討する。最終的な判断は規約を読んで確かめること |

## 3. 進め方の案（このチャットで詰める）

1. **やり方を決める**：キーポイント（点）を直接出す小さなモデル（RTMPose系など）か、物体検出＋点か。ブラウザで動かす仕組み（ONNX Runtime Web、TensorFlow.js、MediaPipeのカスタムモデルなど）とiPhoneでの速さを比べる
2. **データを作る**：WORKOUT動画のコマを切り出し、切っ先・柄頭（・鍔）に印を付ける。道具は無料の物（CVAT、Label Studio、Roboflowの無料枠など）。最初は数百枚で試し、足りなければ増やす。暗い部屋・明るい部屋、服の色、得物の種類、振りの速さ（ぶれ）を混ぜる
3. **学習する**：無料で使える計算環境（Google Colab の無料枠など）。結果は「見つけた率」「位置のずれ（ピクセル）」で測る
4. **ブラウザで動かす**：下の「戻すときの形」のとおりの部品にして、iPhoneで速さと精度を確かめる

**データの置き場所に注意**：アプリのリポジトリ（GitHub `hizashi001/suburi-bugeicho`）は**公開**。ヒデキの顔が映る動画・学習データはそこに入れない。非公開の場所（Google Drive、非公開のリポジトリなど）に置く。

## 3.5 データ作りのページ（作成済み：`swordlab.html`、2026-11-05）

本体のチャットで、学習データを作るページを作った。表紙の「刀の学習データ作り」から開く。公開URL：https://hizashi001.github.io/suburi-bugeicho/swordlab.html

- **撮る**：ゲームと同じ置き方で10/20/30秒。1秒3コマを、長い辺960pxのJPEGで端末の中（IndexedDB）に残す。同時に骨格推定の手首・肘の位置も残す（印付けの手がかり・学習の補助に使える）
- **条件の記録**：部屋・光・得物・服・振った人・メモ
- **印を付ける**：切っ先・鍔・柄頭を指で付ける（拡大鏡つき）。「見えない」「このコマを使わない」「前のコマの印を写す」
- **書き出す**：印を付け終えたコマだけを、COCO形式のキーポイント（カテゴリ katana、点 tip・guard・hilt、v=2 見える／0 見えない）と画像のzipにして共有シートへ。座標は画像のピクセル（左右反転なし）。`images[].meta` に条件、`images[].wrists` に骨格推定の手首・肘（0〜1、[x, y, 見えている度合い]、順に左手首・右手首・左肘・右肘）
- 設定は `config/balance.json` の `swordlab`。試験の台本は `tools/test/t32.js`
- 最初の手本として、ヒデキの動画（WORKOUT、21.6秒）から14コマに印を付けた結果がある（本体のチャットでヒデキに渡した `labels.json` と確認用の画像。座標は360×640に縮めたコマのもの）

撮影の目安：まず300〜500枚（試作）、次に1,500〜3,000枚（実用）。数より条件のばらつき（部屋・光・得物・服・人）が大事。



本体はブラウザのJavaScript（ES modules）。次の形の部品にしてもらえれば、本体のチャットで組み込む。

```js
// js/swordtrack.js
export async function createSwordTracker(options) // モデルを読み込む。options: { modelUrl, ... }
// tracker.detect(video, timeMs) → 次の形を返す（見つからなければ null）
// {
//   tip:   [x, y, conf],   // 切っ先。x, y はカメラ映像の 0〜1（左右反転していない元の映像の座標。MediaPipe と同じ）
//   hilt:  [x, y, conf],   // 柄頭
//   guard: [x, y, conf]    // 鍔（取れれば。無ければ省く）
// }
// tracker.close()
```

- 座標は MediaPipe Pose の `landmarks` と同じく「元の映像（左右反転なし）の 0〜1」にそろえる。本体はこれを骨格と組み合わせて、刀の3Dの向きを出す
- 1回の `detect` にかかる時間の目安も書いておく（iPhoneで何ミリ秒か）

## 6. 本体側で今わかっていること（参考）

- 本体の骨格推定：`index.html` の `onPose`。手の3Dの位置は MediaPipe の worldLandmarks（腰を中心にしたメートル）から作っている（`hand3`）
- 居合の判定は今「手が腰の高さから振り出した」か「静止から」（`config/balance.json` の `bout.iaiHipY`）。刀の向きが取れれば、腰に差した刀の向き（鞘の位置）から本当の居合を見分けられる
- 影の刀は今、前腕の向きの延長に描いている（`js/ghost.js`、`ghost3d.html`）
